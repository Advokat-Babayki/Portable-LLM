# Portable LLM & Whisper Launcher (LLM-Legacy)

Портативный ИИ-комбайн: текстовые нейросети (llama.cpp) и распознавание речи
(whisper.cpp) на любом ПК под **Linux** и **Windows**. Без установки, без
настройки окружения — скачал, запустил, работает.

[![Linux tests](https://github.com/Advokat-Babayki/Portable-LLM/actions/workflows/test-linux.yml/badge.svg)](https://github.com/Advokat-Babayki/Portable-LLM/actions/workflows/test-linux.yml)
[![Windows tests](https://github.com/Advokat-Babayki/Portable-LLM/actions/workflows/test-windows.yml/badge.svg)](https://github.com/Advokat-Babayki/Portable-LLM/actions/workflows/test-windows.yml)
[![License: GPL v3](https://img.shields.io/badge/License-GPLv3-blue.svg)](https://www.gnu.org/licenses/gpl-3.0)

## Возможности

- 💬 **LLM-чат** через веб-интерфейс (http://127.0.0.1:8080)
  - режимы: CPU (работает везде) и Vulkan (GPU AMD / Intel / Nvidia)
- 🎙️ **Распознавание речи** Whisper через веб-интерфейс (http://127.0.0.1:8081)
  - режим: CPU
- ⚙️ **Автоподбор параметров** под ваше железо: контекст, слои на GPU,
  потоки, batch, MoE-эксперты (для Mixtral/DeepSeek)
- 🔌 **Свободные порты**: если 8080/8081 заняты — лаунчер сам найдёт другие
- 🛡️ **Краш-логи**: при аварийном завершении сервера отчёт сохраняется в `logs/`
- 🧭 **Информация о железе** и размер моделей в меню
- 🌐 **Автозапуск браузера** при старте сервера
- 💻 **CLI-режим** на Linux: `./Lunix.sh --model qwen2.5-7b --silent --no-ui`
- Модели GGUF для LLM и ggml-модели для Whisper — любые, кладёте сами
- Бинарники **скачиваются автоматически** при первом запуске из официальных
  релизов llama.cpp / whisper.cpp (в репозиторий не загружаются)

## Запуск

### Linux

```bash
chmod +x Lunix.sh
./Lunix.sh
```

### Windows

Запустить `Windows.bat` двойным щелчком (или через командную строку).

> Файл `Windows.bat` — самовосстанавливающийся PowerShell-бутстрап: при
> запуске он переписывает сам себя в чистый cmd-скрипт (не редактируйте
> первую строку `$content = @'` и последние строки `'@` / `WriteAllText`).

### CLI-режим (Linux)

```bash
./Lunix.sh --no-ui                  # без интерактивного меню (запуск + выход)
./Lunix.sh --silent                 # подавить вывод прогресса скачивания
./Lunix.sh --model qwen2.5-7b       # конкретная модель из models/
./Lunix.sh --backend vulkan         # принудительный бэкенд: cpu | vulkan
./Lunix.sh --model m.gguf --silent  # можно комбинировать
```

### Тесты

Единый раннер (bash + PS, нужен `pwsh`):

```bash
bash tests/run-all.sh   # все тесты; --bash / --ps — только подмножество
```

Инструкция по запуску, конвенциям и добавлению новых тестов — в
[`TESTING.md`](TESTING.md).

В CI тесты идут автоматически через GitHub Actions на push в `main` (см.
бейджи выше): `test-linux.yml` гоняет `bash tests/run-all.sh` (все bash-тесты
+ PS под pwsh), `test-windows.yml` — каждый `tests/*.ps1` под PS 5.1 и pwsh 7
+ smoke-запуск реального `llama-server` с моделью и проверку `/health`
(SHA256-pinned артефакты).

При первом запуске скрипт проверит наличие бинарников в `bin/` и
`whisper/bin/`. Если их нет — скачает официальные сборки:

| Компонент | Версия | Источник |
|---|---|---|
| llama.cpp | см. `lib/versions.inc` | github.com/ggml-org/llama.cpp/releases |
| whisper.cpp | см. `lib/versions.inc` | github.com/ggml-org/whisper.cpp/releases |

Версии бинарников заданы **в одном месте — `lib/versions.inc`** (читается и
Linux-скриптом, и Windows-лаунчером, и CI).

Для скачивания нужен интернет и `curl` (Linux — `wget` как запасной;
Windows — встроенный `curl.exe`, запасной вариант PowerShell). Распакованный
архив удаляется; при сбое появится сообщение и ссылки на ручную загрузку.

## Бонус: работа с OpenCode

Если у вас установлен [OpenCode](https://opencode.ai) — запущенную локальную
LLM можно использовать как модель прямо внутри него. Это приятная фича,
основной сценарий (веб-интерфейс) остаётся прежним.

Как это работает:

- Конфигурация ведётся в **глобальном** конфиге OpenCode (Linux:
  `~/.config/opencode/opencode.json`, Windows: `%USERPROFILE%\.config\opencode\opencode.json`),
  а не в папке проекта. Здесь `opencode.json` нет и не создаётся.
- Провайдер `llama-local` — OpenAI-совместимый (`baseURL: http://127.0.0.1:8080/v1`).
- При каждом запуске модели лаунчер автоматически записывает в глобальный
  конфиг **id текущей модели** и **порт** сервера (id модели = имя `.gguf`
  файла, т.к. llama-server запускается с флагом `--alias`).
- Откройте OpenCode в любой папке, команда `/models`, и выберите
  `llama-local/<имя_модели>.gguf`.

Пошагово (Linux):

```bash
# 1) запустите сервер с нужной моделью (он сам обновит глобальный конфиг)
./Lunix.sh --model имя_модели.gguf

# 2) в отдельном терминале откройте OpenCode
opencode
# введи  /models  и выбери  llama-local/имя_модели.gguf
```

Пример (Windows):

```cmd
powershell -NoProfile -File lib\update_opencode.ps1 -Model имя_модели.gguf -Port 8080
```

Нюансы:

- **Сервер должен быть запущен** — OpenCode ходит на локальный порт, модель
  должна быть загружена (иначе соединение будет отклонено).
- Если смените модель — перезапустите сессию OpenCode (конфиг перечитывается
  при старте), id в глобальном конфиге обновится сам.
- При первом обращении к существующему глобальному файлу рядом создаётся
  резервная копия `opencode.json.bak` (Linux и Windows).

> Авто-обновление не трогает другие провайдеры: меняется только блок
> `llama-local` (id + порт). `opencode.json`/`opencode.jsonc` в папке проекта
> исключены через `.gitignore` — персональный конфиг в репозиторий не попадает.

## Модели

### Текстовые модели (LLM)

Файлы `.gguf` положить в папку `models/`:

```
models/
└── qwen2.5-7b-instruct-q4_k_m.gguf   # пример
```

Любая GGUF-модель работает; Q4_K_M — хороший компромисс качество/скорость.

### Модели Whisper

Файлы `.bin` или `.gguf` положить в `whisper/models/`:

```
whisper/models/
└── ggml-small.bin   # пример
```

Официальные модели: https://huggingface.co/ggerganov/whisper.cpp/tree/main
(`ggml-base`, `ggml-small`, `ggml-large-v3-turbo` — по размеру модели).

## Обновление бинарников

Вышла новая версия llama.cpp / whisper.cpp?

1. Поменяйте версии в **`lib/versions.inc`** (это единственный источник их).

2. Удалите старые бинарники (принудительная перезагрузка):

   - Linux: `rm -rf bin/*
whisper/bin/*`
   - Windows: удалить содержимое `bin\` и `whisper\bin\`

3. Запустите скрипт — он скачает свежие сборки.

> Важно: версия llama.cpp и whisper.cpp меняется независимо. Если скрипт
> качает только новую llama — версию whisper не трогайте.

## Публикация в GitHub Releases (по желанию)

Бинарники в релиз выкладывать НЕ нужно — они грузятся сами с официальных
релизов ggml-org. В GitHub Releases достаточно выложить сам проект:

1. Соберите архив проекта: всё кроме `bin/`, `whisper/bin/` и `models/`
   (т.е. `Lunix.sh`, `Windows.bat`, `lib/`, `README.md`, `.gitignore`, `whisper/ui.html`).
2. Создайте Release на https://github.com/<YOU>/<REPO>/releases/new
   с тегом вида `v1.0`, прикрепите этот zip.
3. Пользователь скачивает ~несколько килобайт, распаковывает, запускает —
   всё остальное подтянется автоматически.

## Решение возможных проблем

- **«Не найден curl/wget/tar»** — Linux: `sudo apt install curl tar`
- **Скачивание прерывается / маленький файл** — скрипт покажет ошибку;
  попробуйте ещё раз (встроен retry), проверьте интернет и прокси.
- **Хочу всё вручную** — см. раздел «Официальные сборки» выше: скачайте
  архивы и распакуйте их содержимое в соответствующие папки `bin/` и
  `whisper/bin/`.
- **Модели не видны в меню** — положите `.gguf` / `.bin` модели, как описано выше.
- **Сервер упал (краш)** — отчёт в `logs/crash_<дата>_<режим>.log`:
  код выхода, параметры запуска, последние строки вывода сервера.
  Прикладывайте его при создании issue.
- **Порт 8080 занят** — лаунчер сам найдёт свободный порт и откроет в нём
  интерфейс; загляните в вывод скрипта (например, `http://127.0.0.1:8082`).

## Автоподбор параметров (автотюн)

При выборе модели лаунчер подбирает параметры запуска под ваше железо:

| Параметр | Как подбирается |
|---|---|
| `--ctx-size` | из **метаданных GGUF модели** (родной `context_length`) и фактически свободной памяти: KV-кеш = слои × KV-головы × head_dim × 4 байта, контекст = (свободная память − модель − 768 МБ) / KV; ограничен родным лимитом модели. Если GGUF недоступен — фолбэк по памяти: ≥4 ГБ VRAM → 8192, ≥16 ГБ RAM → 4096, иначе 2048 |
| `--n-gpu-layers` | по размеру модели и VRAM (Vulkan); без GPU = 0 (чистый CPU) |
| `--threads` | число логических ядер CPU |
| `--batch-size` | 256, если хватает памяти (иначе 128) |
| `--ubatch-size` | 512 |
| `--n-cpu-moe` | для MoE-моделей (Mixtral, DeepSeek): кап экспертов в CPU-режиме |

Размер модели лаунчер оценивает по имени файла (Q4_K_M ≈ 4.37 байт/параметр,
F16 ≈ 16, Q8_0 ≈ 8.5 и т.д.) — так автотюн работает и до скачивания файла.
Контекст же берётся из самого файла `.gguf`, поэтому не привязан к таблице и
корректно работает на любом железе (включая запросы длиннее 2048 токенов).

> **Совет.** Если автоподбор не устраивает, задайте контекст вручную:
> переменная окружения `LLM_CTX` (например, `LLM_CTX=4096 ./Lunix.sh`)
> перекрывает автоподбор на обеих ОС.
